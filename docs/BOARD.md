- [ ] **`proc-macro-error2` future-incompat** — transitive; check for an updated upstream
- [ ] **Backup restore drill** — the restic repository has never been restored from; one rehearsal on a scratch node

- [ ] **Split `scout-core/src/store.rs` (13,158 lines)** — DuckDB is the keystone that makes rebuilds slow, but today any edit anywhere in scout-core invalidates this file and the 234 inline tests it carries. Move migrations to `store/migrations.rs`, DTO structs to `store/dto.rs`, table-touching impls to `store/<table>.rs`, tests beside their impl. The `Store` struct becomes a thin facade re-exporting sub-modules (`pub use accounts::Accounts;`, etc.). - [ ] **`pdf-extract` is the only path to `rand 0.10` / `sha2 0.10` (it ships `lopdf`)** — the only feature is "read text out of a ticket PDF", and you've shipped a fallback that draws such PDFs with `pdftoppm` and reads the picture (board 2026-10-13, `bf7f0c4`). If text extraction stays gated on "has a text layer", pipe the others through Chromium too and drop the dep. One fewer C++ in the build graph and the lockfile's `rand 0.10` / `sha2 0.10` rows go with it
- [ ] **`rand 0.9.5` orphan** — appears in the lockfile but `cargo tree -i rand@0.9.5` returns "nothing to print" across `--target all`, suggesting it is pulled in by a transitive target-conditional dep. Consolidate with `cargo update -p rand --precise 0.8.7`
- [ ] **Property tests for the price extractor** — most board cards are regression tests for "the model said this". You almost never test that the normaliser produces a sane answer on adversarial inputs (`€1,000.00`, `100,00 EUR`, `1.000,00 €`, `$1k`, `GBP 12.99p`, leading/trailing whitespace, the cent-vs-decimal trap the README calls out — `6.48` vs `648` — and the OpenGraph-cross-check pair). - [ ] **Fuzz harness for inbound JSON and PDF extraction** — Resend has not always sent byte-perfect payloads; `pdf-extract` has had parser CVEs; the inbox worker is where they meet. A `cargo fuzz` target on the webhook bytes + the PDF byte stream, run for 5 min nightly on CI, costs almost nothing and would have caught the "stamped as no booking" failure that the 2026-10-13 picture-fallback fixed by hand

### Infra (k3s / ops)

The repo deploys through `compose.yaml` for local and `deploy/k8s/` for production. These items are all in the k3s path.

- [ ] **`startupProbe` on the deployment** — `initialDelaySeconds: 5` on liveness is optimistic given a cold DuckDB open + the migration walk + a first Chromium paint. Add a startupProbe that watches `/healthz` and tolerates ~60 s × 5 attempts so a slow first paint is not a CrashLoopBackoff. The probe also makes it visible to `kubectl describe pod` *why* the pod is not yet ready, which a fixed `initialDelaySeconds` hides
- [ ] **`NetworkPolicy` for egress** — the bot fetches arbitrary user-targeted URLs and renders them in Chromium; a compromise exfiltrates over the same channel. Allow-list Kagi, Perplexity, Duffel, Ignav, Resend, Nominatim, eBay, Marktplaats, Bol, Vinted and Telegram's API; default-deny everything else. `kubectl exec` still works for one-off debugging by widening the namespace's policy. Today nothing enforces the smallest-acceptable-egress principle the README claims
- [ ] **Chromium in a pod of its own** — today a renderer taken over by a page has Scout's uid, its keys in the environment and the database a file away. A second Deployment, `scout-browser`, from the same image: no secret, no service-account token, read-only root, 1.5 Gi; a `NetworkPolicy` lets in Scout only and lets out DNS and the public internet, not the cluster; `Renderer` goes remote when `SCOUT_BROWSER_URL` is set; `scripts/check-browser-fence.sh` proves the fence after a deploy. Worth doing with or without the shop desk (`docs/superpowers/specs/2026-11-17-price-watch-and-shop-browsing-design.md`, Part 2)
- [ ] **`ServiceMonitor` / Prometheus scrape** — `/metrics` is on `0.0.0.0:9090` with the comment "deliberately in neither Service nor Ingress" (correct), but nothing *is* scraping it either. A `monitoring.coreos.com/ServiceMonitor` (or a Loki/Promtail pipeline at the node) gives you post-mortems across time, not just at the moment you remember to run `scripts/metrics.sh`
- [ ] **Document the missing `PodDisruptionBudget`** — single replica makes it moot today; record its absence on the deployment notes so a future "scale to 2" knows the eviction story has not been designed
- [ ] **`/version` endpoint on the site** — returns `git_sha`, `rustc_version`, build time, the value of `RUN_BUDGET`, and the model id in use. Makes "what is running" a one-click rather than a deploy-log dive, and gives the admin `/diag` something to quote
- [ ] **JSON logs in production** — `tracing_subscriber::fmt()` is pretty; flip to `.json()` when `SCOUT_LOG_FORMAT=json`, so a k3s pod's stdout ships straight into Loki / a log aggregator without a parser in front. Pretty stays the default locally
- [ ] **Image signing** — `deploy-k3s.sh` produces `scout:<sha>` and the pod has `imagePullPolicy: IfNotPresent`. A compromised local tag serves silently. `cosign sign-blob` over the image after build (or `cosign sign` against a registry if one is introduced) is a small script and removes the silent-substitution attack
- [ ] **A lightweight `/diag` for the admin** — sits between `/debug` (deep) and `/stat` (aggregate). Top-3 counters from `request_log` by hour/day, last 100 errors with trace id, currently running runs and their budget, and the most-recent 5-minute histogram of provider retries. The kind of page an operator opens at 02:00; gated behind `SCOUT_ADMIN_USER_IDS` like `/stat`
