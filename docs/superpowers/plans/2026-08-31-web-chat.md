# The Web Chat — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A page where a member asks Scout a question and watches the answer stream in, sharing the same conversation their Telegram chat uses.

**Architecture:** Five routes in `scout-web` calling core in-process. The client is an ES module served from our own origin, because the CSP forbids inline script. Streaming is `fetch` + `ReadableStream` over SSE, applying W3a's `TextUpdate` exactly as Telegram's renderer does.

**Tech Stack:** Rust workspace (`scout-api`, `scout-core`, `scout-web`), `axum` 0.8 with `axum::response::sse`, `tokio-stream`, and plain browser JavaScript with no framework.

---

## Read this first

**One thing the design document did not settle, decided here.** `AgentEvent`
has four variants and none of them means "finished". So a stream that simply
ends is ambiguous: it could be a completed answer, a `RunOutcome::Busy` that
emitted nothing, or a run that failed. The client cannot tell, and would
leave a spinner up forever on two of those three.

So `scout-web` defines its own SSE envelope. This is a web-layer concern and
deliberately **not** a change to `AgentEvent`, which stays exactly as W3a
shipped it:

```
event: agent
data: {"Answer":{"Append":"The cheapest"}}

event: end
data: {"status":"ok"}
```

`end` carries `{"status":"ok"}`, `{"status":"busy"}`, or
`{"status":"error","message":"..."}`. Every stream ends with exactly one
`end` frame, which is what lets the client stop cleanly.

**The retraction is a security property, not a nicety.** The client keeps an
`answer` string and applies `Append` by pushing and `Replace` by assigning.
A client that only appended would keep the model's reasoning on screen after
the run retracted it. If you find yourself simplifying `Replace` away,
stop — W3a exists because of it.

**Escaping is not optional.** The answer contains text the model took from
web pages it fetched. It reaches the page as untrusted content.

- [ ] **Step 4: Add the two readers**

In `crates/scout-core/src/session.rs`:

```rust
/// The conversation a page should show, without starting one.
///
/// `resolve_conversation` is wrong here twice over: it needs the message
/// text, because after a long gap it asks the model whether the new message
/// continues the old thread, and it creates a conversation when there is
/// none. Opening a page must create nothing.
pub(crate) fn latest_direct(
    store: &crate::store::Store,
    account_id: i64,
) -> anyhow::Result<Option<i64>> {
    let ttl = SESSION_TTL.as_secs() as i64;
    Ok(store.latest_conversation(account_id, "direct", ttl)?.map(|(id, _aged)| id))
}

/// What was said, oldest first, with the tool traffic left out.
///
/// The same line `last_messages_text` draws, kept structured rather than
/// flattened: that one exists to feed a classifier a blob, this one exists
/// to be rendered.
pub(crate) fn transcript_of(
    store: &crate::store::Store,
    conversation_id: i64,
) -> anyhow::Result<Vec<scout_api::Turn>> {
    let history = load_history(store, conversation_id, HISTORY_CAP)?;
    Ok(history
        .iter()
        .filter_map(|m| match m {
            LlmMessage::User { content } => text_of_user(content).map(|text| scout_api::Turn {
                role: scout_api::Role::You,
                text,
            }),
            LlmMessage::Assistant { content, .. } => {
                text_of_assistant(content).map(|text| scout_api::Turn {
                    role: scout_api::Role::Scout,
                    text,
                })
            }
            _ => None,
        })
        .filter(|t| !t.text.trim().is_empty())
        .collect())
}
```

`text_of_user` and `text_of_assistant` are the two `filter_map` bodies that
`last_messages_text` already contains inline. Extract them into named
functions and have `last_messages_text` call them too, so the rule about
what counts as sayable text lives in one place rather than two that can
drift. Do not change `last_messages_text`'s output — its test asserts the
exact string.

- [ ] **Step 3: Implement the handler**

```rust
/// Why a stream stopped. `AgentEvent` has no "finished", so a stream that
/// merely ended would be ambiguous — a completed answer, a refused run and a
/// crash all look identical to a client, and two of the three would leave a
/// spinner up forever. Every stream ends with exactly one of these.
#[derive(serde::Serialize)]
#[serde(tag = "status", rename_all = "lowercase")]
enum End {
    Ok,
    Busy,
    Error { message: &'static str },
}

/// One thing that goes down the wire, and which SSE event name it takes.
///
/// `AgentEvent` is serialised untouched under `event: agent`, so the browser
/// and Telegram consume the identical shape — the protocol W3a defined, not
/// a second one for the web.
enum Frame {
    Agent(scout_api::AgentEvent),
    End(End),
}

impl Frame {
    fn into_sse(self) -> Result<axum::response::sse::Event, axum::Error> {
        use axum::response::sse::Event;
        match self {
            Frame::Agent(e) => Event::default().event("agent").json_data(e),
            Frame::End(e) => Event::default().event("end").json_data(e),
        }
    }
}
```

The handler: resolve the account, refuse a non-member, check the CSRF header
with `csrf_ok_for`, check the daily cap with `session::over_daily_cap` and
send an `End::Error` carrying its sentence if it refuses, then resolve the
conversation with `session::resolve_conversation` and spawn the run.

The ordering inside the spawned task matters and is easy to get wrong:

```rust
    let (agent_tx, agent_rx) = tokio::sync::mpsc::unbounded_channel();
    let (frames, rx) = tokio::sync::mpsc::unbounded_channel();
    tokio::spawn(async move {
        // Forward events as they happen. `run_agent` drops its sink when it
        // returns, which ends this loop — so awaiting the pump below is what
        // guarantees `end` is last rather than racing the final tokens.
        let pump = {
            let frames = frames.clone();
            tokio::spawn(async move {
                let mut agent_rx = agent_rx;
                while let Some(event) = agent_rx.recv().await {
                    let _ = frames.send(Frame::Agent(event));
                }
            })
        };
        let outcome = scout_core::run::run_agent(&core, agent_tx, &run, &text).await;
        let _ = pump.await;
        let _ = frames.send(Frame::End(match outcome { .. }));
    });
```

Map the outcome: `Ok(RunOutcome::Answered(_))` → `End::Ok` (the answer
already went out as `Answer` updates), `Ok(RunOutcome::Busy)` → `End::Busy`,
`Err(e)` → `End::Error { message: run::agent_error_message(&e) }`.

Create `crates/scout-web/src/chat.test.mjs`:

```js
import { test } from 'node:test'
import assert from 'node:assert/strict'
import { applyUpdate, escapeHtml, linkify } from './chat.js'

test('a Replace clears what was shown rather than extending it', () => {
  // The browser half of the protocol's security property: reasoning the
  // run retracts must leave the screen.
  let answer = ''
  answer = applyUpdate(answer, { Append: 'secret reasoning' })
  answer = applyUpdate(answer, { Replace: '' })
  answer = applyUpdate(answer, { Append: 'The answer' })
  assert.equal(answer, 'The answer')
})

test('an answer is escaped before it reaches the page', () => {
  // The model writes from pages it fetched. This is untrusted text.
  assert.equal(escapeHtml('<img src=x onerror=alert(1)>'), '&lt;img src=x onerror=alert(1)&gt;')
  assert.equal(escapeHtml('5 > 3 & 2 < 4'), '5 &gt; 3 &amp; 2 &lt; 4')
})

test('a url becomes a link and its surroundings stay escaped', () => {
  const out = linkify(escapeHtml('see https://example.com/a?b=1 <b>'))
  assert.match(out, /<a href="https:\/\/example\.com\/a\?b=1"/)
  assert.match(out, /&lt;b&gt;/)
})
```

- [ ] **Step 3: Write the client**

`crates/scout-web/src/chat.js`, as an ES module. Export the three pure
functions so they can be tested, and **guard the DOM wiring** so importing
the module under Node does not try to touch a document:

```js
export function applyUpdate(answer, update) {
  if ('Append' in update) return answer + update.Append
  if ('Replace' in update) return update.Replace
  return answer
}
```

`escapeHtml` replaces `&`, `<`, `>` in that order — `&` first, or the
escapes get escaped. `linkify` turns `https://` and `http://` runs into
anchors; run it **after** escaping, never before, or escaping would break the
markup it produced.

At the end of the file:

```js
// Guarded so `node --test` can import the pure functions above without a
// document to wire to.
if (typeof document !== 'undefined') {
  start()
}
```

`start()` loads `/chat/history` and renders it, wires the send button to
`POST /chat/messages` with the `X-Scout-Csrf` header read from the page's
`<meta name="csrf">`, reads the SSE stream with `fetch` and a
`ReadableStream` reader, applies each `agent` frame, and stops on the `end`
frame — showing the message for `busy` and `error`. On a read error before
`end`, show the dropped-stream notice and a reload button: the run is still
writing its answer server-side, so a reload recovers it.

- [ ] **Step 4: The check that cannot be done locally**

**Server-sent events through a reverse proxy is where streaming quietly
dies.** Buffering turns a stream into one delivery at the end: perfect on
localhost, broken in production, and no test catches it.

After deploying, from outside the cluster:

```bash
curl -N -sS https://goodscout.fyi/chat/messages \
  -H 'Content-Type: application/json' \
  -H 'X-Scout-Csrf: <token from the page>' \
  -H 'Cookie: __Host-scout_session=<your session>' \
  --data '{"text":"hello"}'
```

Watch whether frames arrive progressively or all at once at the end. `-N`
disables curl's own buffering so what you see is what the network did. If
they arrive in a lump, the ingress is buffering and needs
`traefik.ingress.kubernetes.io/router.middlewares` or an equivalent — do not
declare the feature done before this is confirmed.

## What this deliberately does not do

- **Photo upload.** `describe_photo` exists, but multipart handling, size
  limits and storage are their own spec.
- **A stop button.** Needs a cancel endpoint and a way to abort mid-stream.
- **Marking where a thread restarts.** History loads read-only and
  `resolve_conversation` decides afterwards, so a visitor can see history,
  ask a question, and have the gap-check start a fresh thread. Telegram
  already behaves this way invisibly; showing it needs the send path to
  report that it started a new conversation.
- **Changing the landing page**, which still says Scout lives in Telegram.
